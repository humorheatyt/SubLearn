# Architecture and product decisions

Decisions are intentionally explicit so later contributors can revisit them. **ASSUMPTION** marks a choice made without asking the user, as requested.

## Initial decisions (Phase 0)

1. **ASSUMPTION — Target devices.** `minSdk 26` (Android 8.0) is chosen to include Poco X3 Pro's Android 12 / API 31 while keeping Media3 and modern storage/lifecycle APIs practical. `compileSdk`/`targetSdk` will be the latest stable level supported by the pinned Android Gradle Plugin and CI. No Android 12-only dependency is introduced; Android 12 is a first-class CI smoke target.
2. **ASSUMPTION — Modular boundaries.** Use Kotlin, Jetpack Compose + Material 3, Media3, Coroutines/Flow, Room, typed DataStore, Koin, OkHttp and the Gradle version catalog in `app`, `core:*` and `feature:*` modules. Pure subtitle/repeat logic stays Android-free for fast tests; OS/network capabilities are injected behind interfaces.
3. **ASSUMPTION — Product design.** Use a calm cinematic dark-first surface with warm parchment/amber learning accents, a restrained indigo accent for interactive learning cards, large rounded touch targets, motion only for feedback/context, and full light/dark/AMOLED variants. This supports video focus while giving words a distinct readable hierarchy. All visual primitives are tokens, not per-screen literals.
4. **ASSUMPTION — UI language and direction.** The default resources are English; Persian translations are provided in `values-fa`. Direction is selected for each text run/surface (English learning text LTR, Persian native text RTL), not inherited globally from whichever subtitle happens to be shown.
5. **ASSUMPTION — Language policy.** The initial installed language pair is English learning + Persian translation. Language IDs are BCP-47 values and providers do not hard-code Persian in their API shape; unsupported/new-language UI remains gated until complete localization and provider support exist.
6. **ASSUMPTION — App license.** License SubLearn's original code under Apache-2.0. None of the referenced GPL repositories or unlicensed owner repositories is copied. Apache-2.0 is permissive and includes an express patent grant; it does not change third-party licenses.
7. **ASSUMPTION — Media decoder modes.** Provide `AUTO`, `HARDWARE`, `SOFTWARE`, `HARDWARE_PLUS` only when Media3 can select a matching decoder. `AUTO` delegates to MediaCodec; `HARDWARE` prioritizes hardware codecs; `SOFTWARE` prioritizes a software codec if the device exposes one and otherwise reports unsupported; `HARDWARE_PLUS` prioritizes hardware with decoder fallback. No FFmpeg binary/extension is added because its distribution/licensing and ABI build cost are disproportionate for v0.1.0. Never silently claim hardware/software if selection cannot be verified.
8. **ASSUMPTION — Streams and network.** Local files and direct HTTP(S) streams are supported by Media3. No DRM bypass, downloader, hidden endpoint, embedded browser, or YouTube scraping is implemented. Network is used only for user-entered media URLs, explicit AI calls, and ML Kit model download; media/subtitle parsing and saved data stay local.
9. **ASSUMPTION — Translation.** Use the official ML Kit on-device Translation API for English↔Persian with explicit user-initiated model download/status. Translation after successful model download is local. No extracted `.bipe`/TFLite/other model is bundled. Translation failure is presented; source subtitle text remains intact.
10. **ASSUMPTION — AI privacy.** Gemini is the initial default provider selector but no default key is shipped; OpenAI and Anthropic are optional provider implementations. The user enters a key and explicitly invokes AI. Keys are stored only as Android Keystore-encrypted, no-backup app-private ciphertext, excluded from settings export. The selected block/context is sent to the chosen provider over HTTPS; AI cannot work offline and this is shown in UI.
11. **ASSUMPTION — AI prompt context.** Default context includes up to ten preceding subtitle blocks and the film title/timestamps, with each piece configurable. User prompt is editable. Output is an API response, not an inferred/synthetic fixture.
12. **ASSUMPTION — Dictionary boundary.** No dictionary content ships. `DictionaryProvider` is an interface with a disabled `NotImplemented` provider for now. Any future SQLite import must be selected by the user and pass a documented schema/validation gate. The source project's extracted database and model rights question is tracked as `REQ-001`.
13. **ASSUMPTION — Word level.** No third-party CEFR/frequency wordlist is shipped until its redistribution license is verified. `WordLevelProvider` falls back to user-known state and manual-level preference; it never invents a CEFR label.
14. **ASSUMPTION — Storage and permissions.** Prefer `ACTION_OPEN_DOCUMENT` / Storage Access Framework persisted URI grants. Request `READ_MEDIA_VIDEO` only when using Android 13+ broad MediaStore browsing; no broad legacy storage permission. History stores a URI and display metadata, not copied video bytes.
15. **ASSUMPTION — Settings migration.** Use a typed `AppSettings` schema with a persisted schema version and pure migration functions. JSON export/import excludes secrets and unknown fields are tolerated for forward compatibility.
16. **ASSUMPTION — Reference licenses.** No reference implementation code is copied, so no MIT attribution from DualSub Replay is required as a source notice. GPL-3.0 references are ideas-only. ProudVocab and dictionaryproject report no declared license in the GitHub metadata audit; only the user's explicitly permitted *visual idea* from ProudVocab and the dictionaryproject's non-proprietary result categories are used.
17. **ASSUMPTION — Release signing.** Debug APKs use the standard Android debug signing configuration in CI. No keystore or release signing secret is committed. The initial GitHub Release is unsigned beyond normal debug signing and its checksum/source commit is published with the artifact.
18. **ASSUMPTION — Phase execution.** The user's fixed Arena branch is the only branch used; `phase/N-name` labels organize implementation and docs, not branch creation. A PR is opened from `arena/4386d633-sublearn`; merge/release are attempted only after observed CI success and repository permission allows it.

## Follow-up decision log

19. **2026-10-08 — ASSUMPTION — DI framework.** Use Koin rather than Hilt: the graph is small, the existing app module already has Koin dependencies, and Koin avoids adding code generation. This changes only DI wiring, not the `core`/`feature` boundaries.
20. **2026-10-08 — ASSUMPTION — SAF folder access for sidecars.** A single-document `ACTION_OPEN_DOCUMENT` grant cannot reliably enumerate sibling documents. Add an explicit user-selected SAF folder browser so the app can list videos and search matching subtitle files under the same persisted tree grant. Opening a standalone document remains supported; folder selection is the reliable auto-sidecar path.
21. **2026-10-08 — ASSUMPTION — subtitle-layer persistence.** Persist the last subtitle URI and its selected layer in Room; bump the pre-release database from schema 1 to 2 with a nullable-column migration. Existing videos without layer metadata fall back to filename language detection, then the learning layer.
22. **2026-10-08 — ASSUMPTION — finite auto-repeat count.** `repeatCount` represents additional repeats after the initial pass; the controller is given `repeatCount + 1` total passes. A one-tap repeat uses exactly two passes. Repeat/navigation/seek/play controls cancel the active repeat session to prevent stale cue ranges affecting another item.
23. **2026-10-08 — ASSUMPTION — user-word highlighting.** Highlight tokens from saved My Words in their own style; known words may override that style with a separate style. POS and phrase styles remain disabled until the LATER analyzer exists.
24. **2026-10-08 — ASSUMPTION — external PDFs.** Do not read a PDF while the provider is disabled. Detect a PDF open/share intent, route to Learn, and explain that PDF learning is Coming Soon; the disabled Learn entry is backed by the LATER provider/flag.
25. **2026-10-08 — ASSUMPTION — local validation toolchain.** Restore the official Gradle 8.9 wrapper JAR and use a temporary JDK 21 from PyPI for local attempts, but do not commit temporary JDK/distribution/build data. Local Gradle execution is blocked by outbound host policy; a GitHub Actions build is configured as the next independent verification path.
26. **2026-10-08 — ASSUMPTION — ML Kit licensing.** Use the explicitly requested official Google ML Kit Translation API, but its Android artifact is covered by Google ML Kit Terms of Service rather than a permissive OSS license. No model is bundled. Track this exception for owner/legal review before release; see `REQ-003`.

Update this log whenever an assumption changes, an external capability is rejected, or a spec behavior is narrowed. Include impact and migration notes; don't silently change a NOW feature into a demo.27. **2026-10-08 — ASSUMPTION — release signing bootstrap and APK transport.** A persistent RSA-4096 release key is generated by the agent and kept **outside** the repository (workspace `sublearn-signing/`, mirrored into GitHub Actions secrets `SUBLEARN_KEYSTORE_*` as soon as the integration token gains the Secrets permission — REQ-006). Never commit keystores. Because this sandbox can neither write Actions secrets nor download CI artifacts (artifact storage host is blocked) nor upload release assets (`uploads.github.com` is blocked), v0.x releases use a two-phase pipeline: `release.yml` (on `v*` tag) builds/tests and stages unsigned APKs on a throwaway `release-staging/<tag>` branch; the agent signs them locally with `apksigner` (Android build-tools, Apache-2.0, used as a build tool only) and pushes a `signed/` directory; `publish-release.yml` verifies signatures, creates the GitHub Release (arm64-v8a, armeabi-v7a, x86_64, universal + SHA256SUMS), and deletes the staging branch. Pushes made by the workflow `GITHUB_TOKEN` never trigger other workflows, so the unsigned staging push cannot publish. Once the secrets exist, `release.yml` signs and publishes directly and the staging path becomes a fallback. The staging branch is temporary release infrastructure, not product code; all product work stays on the session branch → `main`.
28. **2026-10-08 — ASSUMPTION — UI tests on the JVM.** Compose UI smoke tests run under Robolectric (API 31 = Android 12) in the blocking verify job so UI verification is deterministic; the instrumented API 31 emulator job remains as a non-blocking extra (`continue-on-error`) because hosted-runner KVM emulation is flaky and must not gate releases. Honest status is recorded in CHECKLIST/KNOWN_ISSUES.
